# Algorithm Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Score every company with 25 deterministic price-based algorithms (plus 8 registered phase-2 value/quality algorithms that say "needs X"), show them with a chart each in a new dashboard menu, and let them feed the final long/short scores through one capped blend weight that defaults to 0.

**Architecture:** A pure-Python registry in `src/ier/algos/` computes `AlgoResult`s from the company's price bars (plus the sector index series and peer momentum). Results persist in a new `algo_scores` table, are combined into a `Composite`, and are blended into the scorecard in `build_scorecard` with weight `blend_weight` (config, default 0, hard max 0.30). The API serves scores and chart series; the Next.js dashboard renders them with hand-built SVG components.

**Tech Stack:** Python 3.12 stdlib maths (no new dependencies), SQLAlchemy + alembic, FastAPI, Next.js 15 / React 19 / vitest, pytest.

**Spec:** `docs/superpowers/specs/2026-11-21-algorithm-library-design.md` (approved by the owner 2026-11-21)

## Global Constraints
- No buy/sell/order wording anywhere (tests enforce); use "positive lean", "negative lean", accumulate/hold/reduce/avoid/insufficient evidence.
- Every score is 0-100 with a raw value, a one-line reason and the as-of date; missing input gives `score=None` with a reason, never a guess.
- All thresholds and weights are PLACEHOLDER, uncalibrated, and listed in `docs/PLACEHOLDERS.md`.
- `blend_weight` default 0.0; hard maximum 0.30 enforced in code; with 0 every existing score, signal and fingerprint-independent output is unchanged.
- No new Python or npm dependencies; no model calls (no Groq tokens); runs on a 4 GB server.
- Data files are the audit trail: each stored score references the price `Source` it came from.
- No intraday, candlestick, ADX or ATR (price files carry date, close, volume only).
- Existing rule scores, signal bands and news/social display-only status are not changed.

## Review Focus
- A company with fewer bars than an algorithm's `min_history`: that algorithm is `None` with reason "needs N daily prices", nothing raises (Task 3, 7).
- Price rows with zero, negative or non-finite closes, duplicate dates or gaps: dropped or `None`, never a crash or `inf` (Task 2, 3).
- Stale prices (last bar older than `max_stale_days`, default 10 calendar days): every algorithm `None` with reason "prices stale (last <date>)" (Task 7).
- Missing sector index series or fewer than 3 peers: relative-strength algorithms `None` with a reason (Task 6).
- Bad `algos.yaml` (negative, non-numeric or above 0.30 blend weight): non-numeric/negative raise `ValueError`, above 0.30 is clamped to 0.30 with a note (Task 1, 9).
